# 新版 DailyNews：网页简报 + 邮件提醒

2026-11-12。状态：用户已批准（2026-11-12），含下文“用户的决定”。前置：[服务器 Agent 设计](design-server-agent.md)（已上线 0.1.1）。

## 为什么要做

用户在阿里云上有一个旧的每日新闻简报（账户 `newsbot`、代码 `/srv/news-briefing`、23:20–23:50 准备，00:00 发邮件）。它能用，但：

- 每天有大量和昨天重复的内容；
- 版式粗糙，是长段文字，不好快速扫读；
- 不能换主题，也不能方便地调整偏好；
- 难以照看（这一点已由服务器 Agent 解决）。

另外，用户每天在 YouTube / TikTok 看 AI 早报视频（创作者用 AI 搜集 AI 公司和科技行业的新闻）。用户希望**把自己的文字简报和这类 AI 早报合到一个地方**，不用看两个来源。用户明确不要求做视频。

## 用户怎么读（用户原话整理）

- **早上**在 Mac（开始一天时）或手机（在路上）上**扫标题和摘要**，了解世界大事和关心的领域（尤其政治），重要条目读前几段。
- **下午**经常回来**点开细节或原始来源**。
- 跳过：昨天已经看过的重复报道；版式混乱的大段文字。
- 想要：按类别筛选（如政治、科技、财经）；干净、可快速扫读的版式；**智能去重**：只是昨天新闻后续的报道要隐藏或归并成“更新”。
- 形式：用户选定**网页**（跨设备、可回看）；邮件只做提醒或摘要，附网页链接。

## 目标

1. **每日一期网页简报**，手机和 Mac 浏览器都好读：
   - 顶部是当天“要闻”若干条，下面按类别分组；
   - 每条：标题、2–3 句摘要、来源名和原文链接；可展开看更长的摘要（多来源综合）；
   - 类别筛选（至少：政治、国际、科技、AI、财经；类别可配置）；
   - 浅色 / 深色主题可切换，并记住选择；
   - 往期归档：按日期浏览以前的各期。
2. **跨天去重与“后续”归并**：
   - 同一事件的多篇报道合并成一条“事件”；
   - 与最近若干天（默认 7 天）已出现的事件比对：没有新进展的不再出现（只在页底计数“已隐藏 N 条旧闻”，可展开）；有新进展的显示为“后续”，一句话说明新变化，并链接到之前那期。
3. **AI 早报**是其中一个类别（AI / 科技行业），来源覆盖 AI 公司官方博客与发布、科技媒体等，地位与其他类别相同，可以单独筛选。
4. **邮件提醒**：每天一封，含当期要闻标题（默认前 5 条）和网页链接。失败由服务器 Agent 告警。
5. **偏好可调**：类别及其权重、来源列表、关注/屏蔽关键词、每类条数、默认主题。生成和提醒的时间是 Agent 作业的计划，在 Agent 页面改，不在设置文件里。都在一个设置文件里（见“偏好与设置”）。
6. **作为普通 Agent 作业运行**，失败、超时、错过都走 Agent 已有的告警。

## 非目标

- 视频。音频朗读（TTS）留作以后的可选功能，第一版不做，但数据结构不要妨碍以后加。
- 多用户、评论、社交分享。
- 在 PanelLab 后端或 Agent 里写任何新闻专用代码（[Agent 设计](design-server-agent.md)第 5 条“通用”原则）。
- 迁移或改动旧 DailyNews。新版证明可靠前，旧版照常运行。

## 反目标（技术上能用也算失败）

- 简报网页任何人都能打开（未加保护地暴露在公网）。
- 每天的 AI 费用不受控、悄悄上涨。
- 用户仍然天天看到昨天的旧闻。
- 摘要编造原文没有的内容，或没有原文链接可查。
- 一天没生成成功，用户却不知道。

## 已定的做法

- **网页为主，邮件为辅**（用户决定）。
- **视频不做，音频以后再说**（用户决定）。
- **独立程序 + Agent 作业**：DailyNews 是一个独立的 Python 程序，以 `panellab` 用户运行，由 Agent 按计划调用（Agent 设计已定的方向）。

## 我的决定（用户可推翻）

- **代码放在 PanelLab 仓库的 `apps/dailynews/`**，自带测试和安装说明，不导入 `backend/` 或 `agent/` 的任何代码。理由：和 PanelLab 一起版本管理、一起评审，同时保持 PanelLab 本体通用。部署到服务器 `/srv/dailynews`，属主 `panellab`。
- **生成静态网页**：每期生成一组 HTML/CSS/少量 JS 和一个 JSON 数据文件，不跑常驻 Web 服务。筛选、主题切换、展开都在浏览器里完成。静态文件安全面最小，也不增加常驻进程。
- **流水线**（每个阶段的结果都落 SQLite，可单独重跑）：
  1. 采集：按来源列表抓取（RSS/Atom 优先；个别来源需要时再加专用抓取器），只取标题、链接、发布时间、摘要/正文片段；
  2. 归并：同一天内把同一事件的报道聚成“事件”；
  3. 跨天比对：与最近 7 天的事件比对，分为“新事件 / 后续 / 无进展旧闻”；
  4. 分类与排序：按类别、来源数量、偏好权重、关键词打分；
  5. 摘要：调用大模型，为每个事件写 2–3 句摘要（后续事件写“新变化”一句），**只依据抓到的原文片段**，并保留来源链接；
  6. 发布：生成当期网页、更新归档和首页；
  7. 提醒：发邮件。
- **两个 Agent 作业**，沿用旧版节奏：`dailynews-build`（生成，默认 23:20，失败时 Agent 重试）和 `dailynews-notify`（发提醒，默认 00:00）。时间可在作业里改。提醒作业发现当天没有生成成功时不发提醒、以非零退出，让 Agent 告警。
- **大模型接口**：使用 OpenAI 兼容的 Chat Completions 接口，默认指向 DeepSeek；地址、模型名、密钥都是配置项；密钥放 Agent 作业的“秘密环境变量”。
- **费用上限**：配置每天的最大调用次数和最大 token 数；超出时剩余事件只用原文首句作为摘要，网页注明“未生成摘要”，并在作业输出里记录。
- **去重方法**：先用便宜的方法（规范化 URL、标题相似度）初筛候选，再对候选对让大模型判断“同一事件 / 后续 / 无关”。不引入向量数据库。阈值和比对天数是配置项。
- **数据保留**：原始抓取 30 天，事件与各期网页永久保留（文字很小）。
- **邮件发送**：DailyNews 自己用 SMTP 发提醒，SMTP 配置与 Agent 告警设置分开（同一邮箱也可以）；密钥同样放秘密环境变量。
- **只用 Python 标准库**（与 Agent 相同，Python ≥ 3.9）：RSS/Atom 用 `xml.etree` 解析，大模型和网页抓取用 `urllib`，HTML 正文提取用 `html.parser` 写一个简单的提取器。服务器不需要 pip、venv 或访问 PyPI。
- **安装与升级**沿用 Agent 的方式：PanelLab 把安装包经 SFTP 上传，用户自己运行一次显示的 `sudo bash …/install.sh`。脚本安装代码到 `/srv/dailynews`（属主 `panellab`）、建数据目录，不碰 nginx。之后的升级走同样的流程。两个 Agent 作业由用户在 Agent 页面按安装说明创建，或由安装说明给出可直接粘贴的作业定义。
- **抓取原文**：对当期排名靠前的事件（默认最多 40 篇文章）抓取原文页面，提取正文前若干段作为摘要依据；抓取失败、付费墙或提取不到正文时退回 RSS 片段，并在条目上标注“仅据标题和简介”。没有 RSS 的 AI 公司博客，第一版只对用户指定的少数几个写专用抓取器。
- **期号与时间范围**：每期以“提醒当天”的日期命名（例如 11-12 23:20 生成、11-13 00:00 提醒的那期叫 11-13），重试越过午夜仍属同一期。采集范围是“上一次成功生成之后”，不是固定 24 小时，所以某天失败不会漏新闻。提醒作业只检查同日期那一期是否已生成。

## 偏好与设置

- 所有偏好在一个 JSON 设置文件里（`/srv/dailynews/settings.json`），附带一份 JSON Schema。
- 按已定顺序，PanelLab 的**通用设置表单**（Agent 设计“后续阶段”第 1 项）在 DailyNews 之前或同时完成；DailyNews 只是第一个声明 `settings_schema` 的作业。设置表单本身另写设计，不在本文范围。
- 设置表单完成前，用户可以在 PanelLab 的远程文件编辑里改这个文件；程序启动时校验，不合法就拒绝运行并报出具体字段。

## 用户的决定（2026-11-12）

1. **访问方式：公网地址 + 密码。** 域名 `panellab.cn`，简报放在子域名 `news.panellab.cn`（子域名是我的决定）。由服务器上已有的 nginx 用 HTTPS 提供，HTTP 基本认证保护整个站点。nginx 配置、证书（Let's Encrypt，certbot）和密码文件由用户按我们给的分步说明自己用 sudo 完成；DailyNews 的安装脚本不碰 nginx。站点目录 `/srv/dailynews/site` 需要让 nginx 用户可读。
2. **大模型：DeepSeek**（OpenAI 兼容接口）。用户表示预算充足；费用上限仍保留作为防失控的保险，默认值放宽（例如每天 2,000 次调用），超出时记录并告警，不静默。
3. **语言与内容：**
   - 简报一律用**中文**；外文来源翻译成中文摘要，标题给出中文译文，原标题保留在展开内容里。
   - **尽量不要中国国内新闻**：主要关于中国国内事务的报道默认过滤；涉及中国的国际关系、外交、贸易等国际新闻保留。过滤规则是设置项（我的决定）。
4. **来源：必须权威、官方、可信**——主要国际通讯社和大型国际媒体、官方机构、公司官方博客；**不用内容聚合站和低质量来源**。旧版来源不沿用。
   - 来源清单写在设置文件里，每个来源标注类别和类型（通讯社/媒体/官方/公司）。程序只接受清单里的来源，不从聚合站或搜索结果引入新来源。
   - 初始清单（实现时逐个核实订阅地址可用，不可用的换同等级来源，最终清单给用户过目）：
     - 国际与政治：BBC World、The Guardian World、NPR World、Deutsche Welle、France 24、Al Jazeera English、NHK World、联合国新闻（UN News）；Reuters 与 AP 若有可用的官方订阅则加入。
     - 财经：BBC Business、Guardian Business、美联储、欧洲央行、IMF 的新闻发布。
     - 科技：Ars Technica、The Verge、MIT Technology Review、Wired。
     - AI：OpenAI、Anthropic、Google DeepMind、Google AI、Meta AI、Microsoft Research、NVIDIA、Hugging Face 的官方博客或新闻页。

## 已核实的服务器条件（2026-11-12，用户在服务器上运行检查）

- 地域 `ap-southeast-1`（新加坡），不在中国大陆：`panellab.cn` 指向它不需要 ICP 备案。
- 境外来源可直接访问：BBC、Guardian、OpenAI、Anthropic 均返回 200；DeepSeek API 可达（未带密钥返回 401）。不需要代理。

## 交给实现者决定

- 网页的具体视觉设计（在“干净、可扫读、手机优先、两套主题”的前提下）；实现前会给用户看样稿。
- 标题相似度算法、打分公式的具体参数（先给合理默认值，可配置）。

## 验证

- 单元测试：用录好的来源样本（固定文件）测试采集解析、同日归并、跨天“新 / 后续 / 旧闻”判定、排序、费用上限；大模型调用用假实现。
- 页面测试：生成的网页在手机宽度下可用，筛选、主题切换、展开、归档链接都能用。
- 实验室：在 Agent 实验室夹具里作为作业跑通“生成 → 提醒 → 失败告警”。
- 用户验收：新旧两版在阿里云上并行至少 7 天，由用户判断重复是否明显减少、版式是否好读；之后用户自己停掉旧定时器。
