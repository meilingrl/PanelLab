# 系统监控远程连接收口

基线为 `6912572`（`feat/ssh-key-auth` 末端），开发分支为 `feat/monitor-pinned-ssh`。目的：交接时确认的旧系统监控 SSH 路径（`AutoAddPolicy`、单独保存密码、可远程 apt/pip 安装）不再绕过工作台的主机指纹固定。依据见[路线图接手重排](feature-roadmap.md#接手后重排2026-11-10)第 2 项。

## 使用上的变化

- 「系统监控」的目标列表改为本机加任务工作区里的服务器。未确认主机指纹的服务器不可选，并提示到工作区确认。密码、私钥和 Tailscale SSH 都沿用工作区的设置。
- 远程采集复用工作区的固定只读采集程序：读取 `/proc`、磁盘和可选的 `nvidia-smi`，不再需要远程安装 psutil，也不再执行安装命令。CPU 占用与网络速率在第二次采样后按服务器启动标识和单调时钟计算区间值；重启、超过 300 秒的间隔或网卡变化会重新建立基线。远程目标也显示负载、GPU 和采集警告，进程列表仍只针对本机。
- 采集程序新增磁盘信息：块设备文件系统按设备去重，容器内显示 overlay 根目录，跳过挂载进来的单个文件，最多 32 项。工作区观测接口随之多出 `system.disk` 字段，现有前端与 MCP 不读取它。
- 移除了旧的远程配置保存接口、远程安装 psutil 接口和 `AutoAddPolicy` 代码；后端源码中已无 `AutoAddPolicy`（有测试守护）。旧版保存的配置与加密密码不会被自动删除：页面提示其存在，由用户确认后删除。传入旧目标 `remote` 返回 410。

使用说明见[用户手册系统监控一节](../user/user-manual.md#5-系统监控)。

## 验证

- 自动化：后端 220 项、前端 160 项、MCP 与启动器 155 项通过，前端生产构建通过。
- 真实 Linux：用项目自带的 Debian OpenSSH 夹具镜像，在回环随机端口启动容器并改为只允许公钥登录，经实际 API 验证。未信任时直接拒绝且不发起 SSH；私钥登录后主机指纹与容器内 `ssh-keygen` 一致；第二次采样得到 CPU 区间占用和网络速率；旧目标返回 410；工作区快照不受影响；旧配置可删除。该次运行发现容器内磁盘显示为 `/etc/resolv.conf` 而漏掉根目录，已在 `65ee837` 修复并复测为 `/`。
- 浏览器：同一夹具上切换到远程目标，显示 CPU、负载、内存、磁盘、网速、流量图和 GPU 不可用提示，未信任的服务器不可选，旧配置提示可见，控制台无错误。[截图](assets/monitor-pinned-remote.jpg)
- 夹具容器已删除，Colima 已停回会话开始时的停止状态。重新构建的 `panellab-ssh-lab:20261103` 镜像保留在 Colima 中供后续复用。启动时 Docker 数据盘可用约 20 GB，此前的 ENOSPC 记录不再代表当前状态。

## 独立审查

实现者以外的审查者只读审查了 `6912572..65ee837`，确认未信任或非本人服务器不会发起 SSH、采样历史按用户和服务器隔离。审查提出的问题已在 `0c70287` 修复并补充回归用例：两个标签页并发轮询时旧样本重置基线与历史、轮询失败或基线重置后流量图不再更新、非 ASCII 数字目标与异常网卡名导致 500、磁盘无容量基数时显示裸百分号。复审在新代码上重跑探针，确认这些问题均已关闭且无回归。

## 边界

- 若远程某个块设备挂起，`statvfs` 会进入不可中断等待，信号和线程都无法打断。采集程序整体有 20 秒上限，接口会返回 503 而不是一直挂起，但远端进程可能残留，且同时影响工作区观测。这种情况较少见，本轮不处理。审查者建议的缓解办法：在线程中为每次 `statvfs` 设短超时并跳过该挂载点，或把磁盘采集放到最后，这样至少能保住 CPU、网络和进程数据。
- 网络速率是整台服务器、非 `lo` 网卡的合计，包含 SSH 采集自身流量；不是按任务归因，也没有历史存储或告警。采样基线只保存在单个后端进程内存中，后端重启或多实例部署时会重新建立。
- 旧的 `monitor_remote_config` 表保留，以免静默删除用户数据；不再有代码读取其中的密码用于连接。
- 未在你自己的服务器、真实 GPU 或经 Tailscale 的连接上实测。
