# PanelLab 改进与验证记录

2026-11-02，本轮从 `f9df941` 开始，工作分支 `feat/production-reliability`。此记录区分已实现、已验证与未完成的生产能力，不作为生产上线批准。

## 产品判断

首个锚点是可审查、可恢复的本机站点变更。目标用户是管理少量 Linux 主机的个人或小团队；核心任务是修改站点配置时看清差异、避免覆盖新改动、失败后能确定下一步。价值假设仍需真实使用者验证，不宣称相对所有面板独有，也没有性能提升数据。

竞争产品的官网显示通用网站设置、备份、部署日志等已有成熟供给。本轮减少泛化功能扩张，把深度投入同一操作链。设计、接口与实施检查项见 [设计](../design/design-safe-site-changes.md) 和 [实施计划](../design/plan-safe-site-changes.md)。

## 已确认的生产边界

| 项目 | 边界与后续工作 |
| --- | --- |
| 认证 | 生产入口防护不撤销已签发 JWT；切生产时需换独立 SECRET_KEY。设置 INIT_ADMIN_PASSWORD 不会自动更改已存在账号的密码，必须另行检查与修改 |
| 多租户 | 共享本机 Nginx/MySQL 只适用于可信运维账号；不是隔离的多租户托管平台 |
| SSH | 终端和监控仍接受未知主机密钥，且终端 token 在 WebSocket URL；需统一可信主机库和短期票据，未在本轮宣称解决 |
| Nginx | test 通过和 reload 命令成功不证明 HTTP 业务健康；master 重载是异步过程 |
| 恢复 | DB、文件与进程之间不存在跨系统原子事务；中断或最终 DB 提交失败可能留下 pending，必须人工核查；不自动重放 |
| 审计 | 配置正文可能含原有手写敏感内容，限授权账号查看；不是自动脱敏的分享报告，也不是防篡改审计系统 |
| 部署 | 示例 Compose 为本地演示；权限、TLS、备份、数据库迁移和依赖锁定仍需部署级验收 |

## 验证记录

后端、生产入口和前端实现均已通过独立任务审查。整分支独立审查覆盖基线 `f9df941` 至 `738a46b` 的代码、集成脚本与说明，规格与代码质量检查通过，无阻断发现；审查未重复执行下述主控已运行的测试。

主控在全新、独立容器上执行 `python scripts/verify_site_change_lab.py`：MySQL 8.4.9 与 Linux Nginx 1.30.6。镜像摘要为 `mysql@sha256:c36050afdca850f23cef85703f84c7531a5ae155a11b5ee1c60acb09937c4084`、`nginx@sha256:0e52bd054126cdc040b1276c0af347aeb02a41b9cfe305d6094767ac30e97949`。已观察到以下真实行为：

- 预览无配置写入；创建站点后 HTTP 返回页面 A，更新后返回页面 B。
- 同一凭证再次执行返回 409；面板外写入配置后旧凭证返回 409。
- 注入不合法 Nginx 指令，真实 `nginx -t` 失败；本次变更返回 failed_restored，数据库仍是原站点参数，HTTP 仍返回 B。
- 重载命令首次故障时，恢复配置后执行真实校验和重载；持续重载故障时记录 recovery_failed，未冒充恢复成功。
- 约 80 KB 的实际配置正文完整进入新 MySQL MEDIUMTEXT 审计列，删除后仍可读取；删除站点后历史保留。
- 脚本在 finally 回收它自己创建的临时容器和文件；没有使用已有业务数据库或系统 Nginx。

独立审查发现并修复了两项：MySQL TEXT 容量不匹配、大写已有域名在大小写敏感数据库中的冲突遗漏。已存在的本分支早期 TEXT 审计表不会由 create_all 自动升级；它们需显式 schema 升级，本次未执行任何真实数据迁移。

局限：这不是 Linux 上全栈部署验收（后端在 macOS Python 3.11，Nginx/MySQL 在 Linux 容器）；未执行负载、断电、数据库网络分区、MySQL 其他版本或公网 TLS 验收。

后端最终检查（`39ba58d`）：`python -m pytest tests -q`，107 passed，1 条 Starlette/httpx 依赖弃用提示，27.83 秒。

前端最终独立检查（`13bb272`）：23 项组件交互测试通过，生产构建通过，`npm audit --omit=dev` 为 0。完整依赖树仍有 4 项 moderate 开发依赖告警，来自测试工具链的传递依赖；未通过破坏性强制升级消除。CI 已加入前端测试步骤，但本轮未推送，未获得远端 CI 结果。

## 下一轮的选择

优先把这条变更链用于真实使用者的非关键试点，衡量是否能在确认前看懂影响、是否能从失败记录独立完成核查。尚无外部用户验收、生产故障数据或性能优势证据。

次级候选是统一终端与监控的可信主机身份、主机密钥固定与短期终端票据；再之后才考虑只读磁盘压力诊断。它们未在本轮实现，避免同时扩展成多机部署平台。
