# MCP任务接入：实现与验证记录

2026-11-05，状态：实现、分任务审查和集成验证通过，整轮审查与远程备份待完成。基线c7f76b7，分支feat/mcp-task-access，复用隔离worktree；上一轮[实时观测记录](live-observation-20261103.md)保留为历史证据。

## 本轮目的

用户要求记下陌生Agent接入/MCP，并授权按主控评估继续开发。已写入[当前路线图](feature-roadmap.md)，本轮优先提供可发现、有参数说明的读取工具，使外部Agent无需阅读项目源码即可找到同一任务现场。范围见[设计](../design/design-mcp-task-access.md)、[计划](../design/plan-mcp-task-access.md)。

## 主控取舍

1. 将MCP接入排在本轮第一位，代价是日志跟随和任务操作顺延。
2. 首版为本地stdio只读工具集，代价是需要本地配置且不能写元数据；仍使用既有账号Bearer，不把工具只读误称为凭证限权。
3. 官方SDK2.3.0固定为可选依赖并安装在独立环境，代价是额外环境维护，不更改已有后端依赖。
4. 保留忽略的审查/夹具材料和此前分支，代价是磁盘占用。

## 验证与边界

开发前git fetch确认c7f76b7与远端上一分支一致、工作区干净。可选SDK在项目外层.venv-mcp安装，后端.venv311保持原依赖；已有LinuxSSH/MySQL测试镜像可用。首版工具实现`897419c`通过主控真实Linux SSH/MySQL→HTTP API→MCP stdio验证：发现8个工具，读取同一任务及启动身份/采样上下文、日志尾部、文件与结果JSON、显式上报记录，路径越界/符号链接/FIFO拒绝。测试脚本正常退出并回收自建服务与容器。工具层完整63项协议/HTTP测试与原CLI3项回归通过。独立审查发现有效SFTP空修改时间被拒绝；`4932d95`修复并保留空时间/读取后空大小，23项针对性测试通过，限定复审通过。另在实现测试中发现SDK会转换字符串null并忽略额外字段，已通过同源参数模型严格验证并覆盖新旧握手。最终读取工具85项与初版配置21项合计106项整套测试通过（48.97秒）；随后仅改善--check失败诊断并新增4项，完整25项配置专项通过（7.05秒），CLI3项回归通过。没有将这两次运行误称为最终110项整套重跑。工具与配置两个任务的独立规格/质量审查通过；原CLI回归仍有既有Starlette弃用提示。

当前计划不变更真实服务器、tailnet或用户Agent客户端配置，不引入内置LLM、远程HTTP MCP、任务运行引擎或独立授权体系。SDK客户端协议验收不等于特定客户端GUI、真实模型判断或生产部署验收。下一步仍按真实使用反馈推进接入便利、日志跟随、常用操作和传输。

服务端自动/传统握手分别实测2026-07-28与2025-11-25；stdout协议帧也通过原始JSON-RPC检查。该证据证明MCP客户端能够发现和调用，不代表某一聊天产品的配置界面或模型自主规划已验收。

## 使用与收尾

按[接入指南](../user/mcp-access.md)在独立环境安装可选依赖，准备现有账号凭证文件，使用--check与--print-config后由用户将配置加入所选MCP客户端。生成器不读取令牌内容、不联网、不修改客户端；检查只返回账号服务器数量，HTTP失败给出固定脱敏状态/恢复提示。

已补充独立MCP CI作业，现有后端/前端作业及main/master/PR触发范围不变。当前功能分支备份不会触发该CI，不能据此声称远端CI通过。后端/前端产品代码没有变化，本轮未重复其完整套件或浏览器验收；原功能通过CLI回归和真实协议脚本复核相关路径。

两个真实夹具运行均正常退出并回收其容器/进程，未保留测试服务。工作区、.venv-mcp依赖以及`.superpowers/sdd/plan-mcp-task-access/`审查证据保留供复核；原有资产与其他项目服务未修改。
