# 首次使用彩排

基线为 `3dba8c2`（PR #1 合并后的 main），开发分支为 `chore/first-use-rehearsal`。用户确认尚无旧部署、也还没在自己的服务器上用过，因此先按新用户路径完整走一遍，修掉途中的阻碍，再交给用户试用。依据见[路线图接手重排](feature-roadmap.md#接手后重排2026-11-10)第 4 项。

## 彩排路径

在本机 Colima 上用 `scripts/local_panel.py --state-dir <临时目录> --port 8768` 从当前代码构建并启动（独立实例，不影响默认 `data/local-panel`）。远端用项目自带的 Debian OpenSSH 夹具，改为只允许公钥登录，用带口令的 Ed25519 私钥，并在其中运行模拟训练程序写日志。经浏览器依次完成：登录 → 添加服务器（选 SSH 私钥）→ 上传私钥 → 核对指纹（与容器内 `ssh-keygen` 一致）→ 信任并连接 → 登记任务（找进程、选目录和日志）→ 观测与日志跟随 → 系统监控切到远程目标。整条路径可以走通，期间发现以下阻碍。

## 发现与处理

| 现象 | 处理 |
| --- | --- |
| 添加服务器时选了私钥，刷新页面后连接卡的认证方式回到「SSH 密码」；此时信任会固定为密码模式，之后连接失败 | 未固定指纹且已保存私钥的服务器默认选私钥（`7d54328`） |
| 采集警告以英文原样显示，例如没有 GPU 的机器显示「GPU unavailable」 | 统一译为中文说明（`dff557f`） |
| 查找进程后没有结果数量提示，唯一可见的反馈是无关的 GPU 警告 | 显示「找到 N 个进程」或「没有匹配的进程」，进程搜索中不再显示 GPU 警告（`42d73df`） |
| 选中进程后仍需手动浏览到它所在的目录 | 用该进程的工作目录预填任务目录并提示；用户自己浏览选过的目录不会被覆盖（`42d73df`） |
| 启动器下「系统监控 · 本机」列出 `/etc/resolv.conf`、`/etc/hostname`、`/etc/hosts` 而没有 `/`，且「本机」实为面板容器 | 跳过挂载进来的单个文件、按设备去重、始终先报告根目录；在容器中运行时目标改名为「面板容器」并说明不是你的电脑（`b7a7c2e`） |
| 主机或用户名填错后，只能到「用户中心」修改，工作区里没有入口 | 连接卡新增「编辑连接」；修改主机、端口或用户名仍会使已确认的指纹失效（`c8f324a`） |

未处理：「用户中心」里的旧版新建服务器表单只有密码方式，与工作区的添加表单不一致。工作区已覆盖完整流程，暂不改动。

## 验证

- 自动化：后端 224 项、前端 172 项通过，前端生产构建通过。新增用例覆盖上表各项，包括保存失败时保留表单、切换服务器关闭编辑表单、用户已选目录不被进程目录覆盖。
- 实际应用：用同一启动器重新构建并启动，数据保留。浏览器中确认：监控目标显示「面板容器」及说明，磁盘只有 `/`；编辑连接把端口改为 2222 后显示「需要确认指纹」，改回 22 后恢复「已固定指纹」；新建一台已保存私钥但未信任的服务器，刷新后默认选中私钥；查找进程显示「找到 2 个进程」，选中后任务目录填为该进程的工作目录。[截图](assets/first-use-process-directory.jpg)
- 收尾：彩排实例的容器、网络、数据卷和镜像以及夹具容器均已删除，临时私钥与凭据目录已清除，Colima 已停回会话开始时的停止状态；`panellab-ssh-lab:20261103` 夹具镜像保留供复用。

## 独立审查

实现者以外的审查者只读审查了 `ac4350f..8477c98`，未发现严重问题：迟到的响应不会落到其他服务器或表单，编辑连接不能绕过指纹固定，密码字段只在密码模式发送且保存后清空。四项低风险问题已在 `071325a`、`8c1e9da` 修复并补充回归用例：与根目录同一设备的其他挂载点重复列出；用户已改选认证方式后，迟到的私钥查询仍把它改回私钥；改地址时已保存的密码或私钥会沿用到新地址而无提示（仍需信任新指纹才会发送，现加提示）；取消绑定进程后预填目录残留，以及进程工作目录已删除时仍被预填。复审确认四项均已关闭、无回归；复审指出的遗留小问题（从有目录的进程直接切到无可用目录的进程时，上一个建议残留）已在随后提交中一并修复。

## 自己试用时

1. 先 `colima start`，并确认 `docker context use colima`；再进入仓库根目录（本机为 `PanelLab/repo/`，不是外层 `PanelLab/`），`git pull --ff-only` 后运行 `python3 scripts/local_panel.py`，再用 `python3 scripts/local_panel.py password` 查看初始密码，打开 http://127.0.0.1:8765 登录。
2. 「任务工作区 → 添加服务器」，填写平时 `ssh` 用的主机、端口和用户名。只接受密钥的服务器选「SSH 私钥」并上传私钥（建议为面板单独生成一把）。
3. 获取指纹后，在服务器上对界面显示的密钥类型运行 `ssh-keygen -lf /etc/ssh/ssh_host_<类型>_key.pub`（例如 ed25519），或对照云厂商控制台核对，一致再信任。
4. 登记一个正在跑的训练或网站：先「查找进程」选中它，目录会自动填入，再选日志文件。
5. 第二天回来，看观测、日志和系统监控是否还是你需要的样子。请记下卡住或不顺手的地方，以及等待太久的步骤。

## 边界

- 夹具运行在同一台机器的 Docker 网络里，没有覆盖真实公网延迟、云厂商镜像、Tailscale 和真实 GPU。
- 面板容器的磁盘和内存是 Colima 虚拟机的数据，不代表 macOS 本身。
