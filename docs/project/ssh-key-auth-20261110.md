# SSH 私钥登录

基线为 `9e02be5`（`feat/onboarding-log-follow` 之上的接手重排），开发分支为 `feat/ssh-key-auth`。目的：只接受密钥登录的服务器也能接入任务工作台，为真实使用扫清第一步。优先级依据见[路线图接手重排](feature-roadmap.md#接手后重排2026-11-10)。

## 使用上的变化

- 添加服务器或在连接卡选择「SSH 私钥」，粘贴或选择私钥文件，有口令一并填写。支持 OpenSSH、PKCS#8 与传统 PEM 格式的 Ed25519、ECDSA（P-256/384/521）和 2048 位以上 RSA。
- 口令只用于这次解锁，不保存。私钥规范化为不加密的 OpenSSH 文本后，以 `SECRET_KEY` 派生的 Fernet 加密存入新表 `server_private_keys`。界面和接口之后只显示类型和指纹，可替换或删除。删除服务器会一并删除私钥。
- 先核对主机指纹，再用私钥认证，顺序与密码模式一致。私钥模式在保存私钥前不能确认信任或检查连接。终端、文件、观测和日志沿用同一连接，CLI 与 MCP 无需改动。
- 新增的是一张表，没有修改已有列；已有 MySQL 部署启动时 `create_all` 会自动建表。

使用说明见[任务指南](../user/remote-workspace.md#第一次连接)。

## 验证

- 自动化：后端 206 项（新增 14 项私钥用例）、前端 154 项（新增 4 项）通过，前端生产构建通过。用例覆盖口令必需/错误、损坏密钥、公钥/PuTTY 误传、弱 RSA、非 OpenSSH 曲线、超长输入与非对象请求不回显，以及所有者隔离和主机指纹变化时不认证。
- 真实协议：本机以当前用户临时运行 OpenSSH `sshd`（仅回环、仅公钥认证、配置与密钥均在临时目录），通过实际 API 和 Paramiko 验证。带口令的 Ed25519 与 3072 位 RSA PEM 均能登录，RSA 由服务器以 rsa-sha2 签名接受。未授权密钥被拒绝，主机与客户端指纹和 `ssh-keygen` 输出一致。SFTP 列目录正常，终端票据在指定目录打开 shell。
- 浏览器：在同一临时 sshd 上通过界面上传私钥、核对指纹、信任并连接成功，[截图](assets/ssh-key-connected.jpg)。保存后页面不再显示私钥文本。
- 测试 sshd、后端与前端开发服务器均已停止，临时文件只在会话临时目录。

## 独立审查

实现者以外的审查者只读审查了 `9e02be5..311d027`，确认主机指纹先于认证、口令不落库、错误不回显、所有者隔离和删除级联均成立。审查提出四项问题，已在 `08fc483` 修复并补充回归用例：非 OpenSSH 曲线导致 500、非对象请求体被校验错误回显、损坏密钥附带口令时误报口令错误、保存途中切换服务器导致私钥面板一直处于忙碌。复审在新代码上重跑探针，四项均已关闭，未发现回归。剩余一项可接受的小问题：损坏的传统 PEM 加密私钥附带口令时仍提示口令错误，因为文件头仍标记为加密，两种情况无法区分。

## 边界

- 私钥的静态保护等同已保存的 SSH 密码：能读取数据库和 `SECRET_KEY` 的人可以解密。建议为面板单独生成密钥，只授权给需要的服务器。轮换 `SECRET_KEY` 后需重新上传。
- 不支持 ssh-agent、硬件密钥（FIDO/`sk-*`）、证书认证、PuTTY `.ppk` 直接导入和每次连接时输入口令。
- 尚未在你自己的服务器、云厂商镜像或经 Tailscale 的私钥连接上实测；Linux 上的 `/proc` 观测本轮未在 macOS sshd 上覆盖，沿用此前 Linux 夹具结论。
- 旧「系统监控」页的远程 SSH 仍是独立实现，不支持私钥，也不做指纹固定，按路线图下一项处理。
